# Specs

One file per epic: `<slug>.md`. Each has the user, the job, acceptance criteria (one per
changed element, edge cases included), what is out of scope, and the data model delta if
the epic touches the schema.

In the one-hour build the user, the job and the scope cut live in the design pass
(`docs/design/design-pass.md`), and the spec's acceptance criteria are its user stories'
Given/when/then lines (section 14), with the critic's S2 findings as rabbit holes.
