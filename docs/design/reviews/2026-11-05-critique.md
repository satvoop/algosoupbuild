FINDINGS
1. S2 section 7: the hypothesis signal (one strategy with runs on 2+ markets) is met by the owner's own walk-through running a seeded strategy on two items, and the 2+ dates leg cannot happen inside the hour. The hypothesis cannot come out false in this build, so it tests nothing about value.
2. S2 sections 7, 11, 12: deleting a strategy or removing an item (section 11) can cascade over or orphan analysis_runs, and that contradicts P1 ("results that are not saved" ruled out) and section 1's "every run stored". The signal query also counts the remaining rows, so deletes undercount it.
3. S2 sections 11 and 14, row 5: S6's acceptance covers only create. Edit, delete, an invalid schema and an unknown placeholder have no criterion. The spec will have no test for the failure path most likely to break every run.
4. S2 sections 13 and 14, row 9: the zero-news degradation ("run on odds alone, stated in the result") is claimed as covered by a story but has no acceptance criterion. Section 13's own rule ("each a story") is not met.
5. S2 section 6, row 12: the only tension written down, P1 vs P3, is not a tension. The real trade is P3 (seeded menu) against the user's freedom to write their own strategy (S6), and that trade is not written down.
6. S2 section 12 and 0.4, row 18 and the module hand-off: Refresh news makes two LLM calls (query writing, relevance scoring), and section 12 records no model-call row for either. news_article keeps only the score and reason. The queries behind an article set are lost, so a run's inputs cannot be reproduced (P1). The module's "one model-call log row" per prompt-and-response is also not met.
7. S2 sections 1 and 0.8, row 13: Currents' free tier requires attribution (Viability row), but no screen (section 11) and no story (section 14) shows it. A licence condition with no acceptance criterion will not be built or tested.
8. S2 sections 1 and 3, row 13: the Feasibility assumption "LLM latency under ~20s" has no kill fact or action. Refresh chains two LLM calls and a fetch in one request, and nothing says what happens on a timeout.
9. S2 sections 0.8 and 3 (A1): the news-prompt experiment that is A1's only evidence was "in flight at drafting", and its result is not recorded. The concept's own "what kills it" goes to the gate without the evidence the session already had in motion.
10. S1 section 8, row 14: seven cuts, no Backlog card for any of them.
11. S1 section 0.2: "Scope fits the hour" is an assertion. Name the first cut if the build overruns (strategy edit/delete, or user-written JSON schemas).
12. S1 section 14: S1's "Feels like P1" is mis-assigned.
13. S1 section 1, row 7: "in one click" on other markets contradicts the per-item flow.
14. S1 rows 1, 6 and 10: no loading or duplicate-run state, and no placeholder list or help in the strategy form.
15. S1 section 12: an edit overwrites the strategy in place (section 8), so the signal counts runs of different prompts under one strategy_id as "the same method". Only the rendered prompt on each run can tell them apart.
16. S0 section 10: "No markets yet" vs events (A4).
